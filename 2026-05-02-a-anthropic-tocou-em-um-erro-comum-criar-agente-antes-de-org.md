# A Anthropic tocou em um erro comum: criar agente antes de organizar o processo.

A Anthropic tocou em um erro comum: criar agente antes de organizar o processo.

Na apresentação "Don't Build Agents, Build Skills Instead", Barry Zhang e Mahesh Murag defendem uma mudança prática na forma de pensar agentes de IA.

A ideia deles é simples de visualizar.

Um agente pode ser muito capaz, mas continua limitado quando não conhece o jeito como uma empresa trabalha.
- Ele não sabe quais padrões seguir.
- Não conhece os exemplos bons.
- Não entende os critérios internos.
- Não sabe quais decisões exigem mais cuidado.
- Não carrega a experiência acumulada do time.

Por isso eles defendem o uso de Skills.

Uma Skill é um pacote de conhecimento para o agente. Pode incluir instruções, arquivos, exemplos, scripts e procedimentos que ajudam a IA a executar uma tarefa com mais consistência.

Para uma empresa, essa leitura é bastante prática.

Antes de multiplicar agentes de financeiro, suporte, vendas, jurídico ou tecnologia, vale olhar para as tarefas que se repetem e perguntar:

O que uma pessoa experiente sabe fazer aqui que ainda não foi documentado?
- Como revisar uma proposta.
- Como montar um relatório.
- Como responder um cliente.
- Como seguir um padrão de qualidade.
- Como usar uma ferramenta interna.
- Como evitar erros recorrentes.

Quando esse conhecimento vira Skill, a IA deixa de depender apenas da inteligência geral do modelo e começa a operar com mais contexto da empresa.

Esse é um ponto importante;
A maturidade no uso de IA não vem só de liberar mais ferramentas para mais pessoas.

Ela também depende de transformar conhecimento operacional em algo que a IA consiga consultar, repetir e melhorar ao longo do tempo.

Empresas que já têm processos mapeados ganham muito com isso. Não porque podem criar dezenas de agentes, mas porque já têm algo valioso para ensinar para eles.
